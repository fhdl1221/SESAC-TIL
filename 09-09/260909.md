## 1. 옵셔널 체이닝 연산자 (?.)

### 옵셔널 체이닝 연산자란?
- 좌항의 피연산자가 null 또는 undefined인 경우 undefined를 반환하고, 그렇지 않으면 우항의 프로퍼티 참조를 이어간다
- 주로 객체 속성을 안전하게 읽고 싶을 때 사용

```js
const obj = null;

const val = obj?.value;
console.log(val);  // undefined
```

- 논리연산자(&&)를 이용하여 단축 평가로 확인을 하는 방법도 있지만, Falsy한 값을 false 취급하여 발생하는 문제가 있다
-> 이럴 때 옵셔널 체이닝 연산자 사용

---

## 2. Nullish 연산자 (??)

### nullish란?
- 좌항의 피연산자가 null 또는 undefined인 경우 우항의 피연산자를 반환하고, 그렇지 않으면 좌항의 피연산자를 반환한다

```js
const test = null ?? 'default';
console.log(test); // default
```

- null이나 undefined가 아닌데 falsy한 값을 저장하고 싶을 때 ?? 연산자를 사용한다

## 3. 생성자 함수

### 생성자 함수란?
- 같은 형태의 객체를 생성하기 위해 사용하는 함수
- 객체를 만들어내는 **객체 생성 틀**
- 생성자 함수명은 **대문자**로 시작
- 생성자 함수는 **new**와 함께 사용
-> new를 사용하면 자바스크립트가 새로운 객체를 만들고 생성자 함수의 this가 그 새로운 객체를 가리키도록 한다

## 4. 프로토타입

### 1. 생성자 함수와 prototype

생성자 함수는 `new` 키워드를 사용하여 같은 구조의 객체를 여러 개 생성할 때 사용한다

```javascript
function Student(name, age) {
    this.name = name;
    this.age = age;
}

const student1 = new Student("판다", 8);
```

`Student` 함수가 생성되면 `Student.prototype` 객체가 만들어진다

```javascript
Student.prototype.activate = true;

Student.prototype.getInfo = function () {
    return `${this.name}은 ${this.age}세 입니다.`;
};
```

`prototype`에는 여러 객체가 **공통으로 사용할 프로퍼티와 메서드**를 정의할 수 있다

---

### 2. `[[Prototype]]` 연결

`new Student()`를 통해 객체를 생성하면 생성된 객체의 `[[Prototype]]`이 `Student.prototype`을 가리키도록 연결된다

```text
Student
  │
  │ prototype
  ↓
Student.prototype
  ↑
  │ [[Prototype]]
  │
student1
```

```javascript
console.log(Object.getPrototypeOf(student1) === Student.prototype);  // true
```

`Object.getPrototypeOf()`는 객체의 `[[Prototype]]`을 확인한다

---

### 3. 프로토타입을 통한 메서드 공유

```javascript
const student3 = new Student("홍길동", 20);
const student4 = new Student("장보고", 30);
```

`student3`과 `student4`는 서로 다른 객체이지만 둘 다 `Student.prototype`에 연결되어 있다

```javascript
console.log(student3.getInfo());
console.log(student4.getInfo());
```

`getInfo`는 각 객체가 직접 가지고 있는 것이 아니라 `Student.prototype`에 있기 때문에 두 객체가 하나의 함수를 공유한다

```javascript
console.log(student3.getInfo === student4.getInfo); // true
```

---

### 4. 프로토타입 체인

`Object.create()`를 사용하면 특정 객체를 새로운 객체의 `[[Prototype]]`으로 연결할 수 있다

```javascript
const user = {
    id: "user",
    activate: true,
    login: function () {
        console.log(`${this.id}님이 로그인 되었습니다.`);
    }
};

const student = Object.create(user);
student.passion = true;
```

```text
student
  │
  │ [[Prototype]]
  ↓
user
 ├─ id
 ├─ activate
 └─ login()
```

`student`에 없는 프로퍼티를 찾을 때 `user`까지 확인한다

```javascript
console.log(student.activate);  // true

console.log(student.passion);  // true
```

`activate`는 `student`가 직접 가지고 있지는 않지만 `user`에서 찾을 수 있기 때문에 사용할 수 있다

---

### 5. `Object.hasOwn()`과 `in` 연산자

### `Object.hasOwn()`

객체가 프로퍼티를 **직접 가지고 있는지** 확인한다

```javascript
console.log(Object.hasOwn(student, "activate"));  // false

console.log(Object.hasOwn(student, "passion"));  // true
```

### `in`

프로토타입 체인까지 확인하여 해당 프로퍼티를 **사용할 수 있는지** 확인한다

```javascript
console.log("activate" in student);  // true
```

즉, hasOwn()은 **직접** 가지고 있는지 확인, in은 프로토타입까지 찾아서 **사용**할 수 있는지 확인

---

### 6. 프로토타입 체인이 여러 단계인 경우

프로토타입은 하나의 객체에만 연결되는 것이 아니라 여러 단계로 연결될 수 있다

```javascript
const greedyStudent = Object.create(student);

greedyStudent.greed = true;
greedyStudent.id = "student01";
```

```text
greedyStudent
      │
      ↓ [[Prototype]]
   student
      │
      ↓ [[Prototype]]
     user
```

따라서 `greedyStudent`에서 프로퍼티를 찾을 때

```text
1. greedyStudent
        ↓ 없으면
2. student
        ↓ 없으면
3. user
        ↓ 없으면
4. 그 상위 프로토타입
```

순서로 확인한다

```javascript
console.log(greedyStudent.activate);  // user에서 찾음 → true

console.log(greedyStudent.passion);  // student에서 찾음 → true

console.log(greedyStudent.missing);  // 찾지 못함 → undefined
```

---

### 7. 프로퍼티 탐색과 같은 이름의 프로퍼티

`greedyStudent`가 `id`를 직접 가지고 있으면 **자신의 값**을 사용한다

```javascript
greedyStudent.id = "student01";

console.log(greedyStudent.id);  // student01
```

`greedyStudent`에서 `id`를 삭제하면 프로토타입 체인을 따라 `user.id`를 찾는다

```javascript
delete greedyStudent.id;

console.log(greedyStudent.id);  // user의 id → "user"
```

즉, **가까운 객체에 같은 이름의 프로퍼티가 있으면 그 값을 우선 사용**

---

### 8. 메서드의 `this`

프로토타입에 있는 메서드라도 메서드를 **어떤 객체를 통해 호출했는지**에 따라 `this`가 결정된다

```javascript
greedyStudent.login();
```

`login()`은 `user`에 정의되어 있지만 호출할 때 점(`.`) 앞에 있는 객체는 `greedyStudent`이므로 `this === greedyStudent`가 된다

```javascript
greedyStudent.id = "student01";

greedyStudent.login();  // student01님이 로그인 되었습니다.
```

즉, **메서드 내부의 `this`는 메서드가 실제로 정의된 객체가 아니라, 호출할 때 점(`.`) 앞에 있는 객체**

### 핵심 정리

```text
생성자 함수
    ↓
prototype 프로퍼티
    ↓
공통 메서드 저장

new 생성자()
    ↓
새 객체 생성
    ↓
[[Prototype]]으로 생성자의 prototype과 연결
```

| ------------------------- | ------------------------------------------ |
| `prototype`               | 생성자 함수가 가지고 있는 프로퍼티이며, 공통 메서드를 저장할 수 있는 객체 |
| `[[Prototype]]`           | 객체가 다른 객체를 참조하는 내부적인 연결                    |
| `Object.getPrototypeOf()` | 객체의 `[[Prototype]]`을 확인                    |
