# 1. Git 기본 개념

## Git이란?
Git은 소스 코드의 변경 이력을 관리하고 여러 개발자가 하나의 프로젝트를 협업할 수 있도록 하는 **버전 관리 시스템**

## Git과 GitHub의 차이

| 구분     | 설명                                           |
| ------ | -------------------------------------------- |
| Git    | 버전 관리 시스템                                    |
| GitHub | Git Repository를 원격에서 저장하고 협업할 수 있도록 제공하는 플랫폼 |

---

# 2. Git의 공간과 파일 상태

Git의 공간과 파일 상태를 구분하는 것이 중요하다

## 2-1. Git의 4가지 공간

```text
Workspace
    │
    │ git add
    ↓
Staging Area
    │
    │ git commit
    ↓
Local Repository
    │
    │ git push
    ↓
Remote Repository
```

### Workspace

개발자가 실제로 코드를 작성하고 수정하는 공간으로, 파일 생성/수정/삭제 등의 작업이 이루어진다

### Staging Area

다음 commit에 포함할 변경 사항을 모아두는 공간

```bash
git add .
```

### Local Repository

commit한 변경 이력이 로컬에 저장되는 공간

```bash
git commit -m "feat: 로그인 API 구현"
```

### Remote Repository

GitHub와 같은 원격 저장소

```bash
git push origin main
```

위의 명령어를 통해 Local Repository의 commit을 업로드한다

---

## 2-2. Tracked와 Untracked

**Tracked / Untracked**와 **Workspace / Staging Area**는 서로 다른 개념이다

### Untracked

Git이 아직 관리하지 않는 파일

```text
새 파일 생성
    ↓
Untracked
```

예시

```bash
git status
```

```text
Untracked files:
  hello.txt
```

`hello.txt` 파일은 아직 `git add`하지 않았기 때문에 Git이 관리하는 파일이 아니다

파일을 계속 수정해도

```text
Untracked files:
  hello.txt
```

상태가 유지된다

---

### Tracked

Git이 관리하고 있는 파일

새 파일을 add 및 commit 하면

```bash
git add hello.txt
git commit -m "feat: 파일 추가"
```

이후 해당 파일은 Git이 관리한다

그 후 파일을 수정하면

```text
modified: hello.txt
```

로 표시된다

---

## 2-3. 파일 상태 변화

```text
새 파일 생성
    ↓
Untracked
    │
    │ git add
    ↓
Staged
    │
    │ git commit
    ↓
Tracked + Clean
    │
    │ 파일 수정
    ↓
Tracked + Modified
    │
    │ git add
    ↓
Tracked + Staged
    │
    │ git commit
    ↓
Tracked + Clean
```

핵심 요약

> `git add`는 변경 내용을 Staging Area에 올리는 작업이고, 새 파일의 경우 Git이 그 파일을 관리 대상으로 인식하게 만든다

# 3. Git 기본 작업 흐름

## 로컬에서 GitHub로

```text
파일 수정
   ↓
git add
   ↓   
git commit
   ↓
git push
```

## GitHub에서 로컬로

```text
Remote Repository
       ↓
   git pull
       ↓
Local Repository
       ↓
Workspace
```

# 4. Git 기본 명령어

## 4-1. 저장소 생성 및 가져오기

### `git init`

```bash
git init
```

`.git` 디렉터리가 생성되고 Git Repository가 된다

---

### `git clone`

이미 존재하는 Git Repository를 로컬로 복제한다

```bash
git clone <repository-url>
```

`git clone`을 하면 `.git`도 함께 생성되기 때문에 **추가로 `git init`을 실행할 필요는 없다.**

### `init`과 `clone`

```text
git init
→ 일반 폴더를 Git Repository로 만든다

git clone
→ 기존 Git Repository를 로컬로 복제한다
```

---

## 4-2. 상태 확인

### `git status`

현재 Git 상태를 확인한다

주로 확인할 수 있는 상태

```text
Untracked files
Changes not staged for commit
Changes to be committed
```

---

## 4-3. Staging

### `git add`

변경 내용을 Staging Area에 추가한다

특정 파일을 추가하려는 경우

```bash
git add hello.txt
```

여러 파일을 추가하려는 경우

```bash
git add hello.txt greeting.txt
```

전체 파일을 추가하려는 경우

```bash
git add .
```

---

## 4-4. Commit

### `git commit`

Staging Area의 변경 내용을 Local Repository에 기록한다

```bash
git commit -m "feat: 파일 추가"
```

---

## 4-5. Commit 이력과 상세 내용 확인

### `git log`

commit **목록과 이력**을 확인한다.

```bash
git log
```

간단하게 확인하려는 경우

```bash
git log --oneline
```

그래프로 확인하려는 경우

```bash
git log --oneline --graph --all
```

---

## 4-6. Branch 관련 명령어

### `git branch`

Branch를 조회/생성/삭제한다

조회

```bash
git branch
```

생성

```bash
git branch feature/my-name
```

삭제

```bash
git branch -d feature/my-name
```

강제 삭제:

```bash
git branch -D feature/my-name
```

---

### `git switch`

Branch를 이동하거나 생성하면서 이동한다

기존 Branch로 이동하는 경우

```bash
git switch develop
```

Branch를 생성하면서 이동하는 경우

```bash
git switch -c develop
```

---

## 4-7. 원격 저장소

### `git remote -v`

현재 연결된 Remote Repository를 확인한다

```bash
git remote -v
```

예시

```text
origin  https://github.com/example/project.git (fetch)
origin  https://github.com/example/project.git (push)
```

---

### `git pull`

원격 Repository의 변경사항을 가져와 현재 Branch에 반영한다

```bash
git pull origin develop
```

---

### `git push`

Local Repository의 commit을 Remote Repository에 업로드한다

```bash
git push origin feature/my-name
```

처음 push하는 Branch라면

```bash
git push -u origin main
```

이후

```bash
git push
```

만 사용해도 main 브랜치로 push가 된다

---

# 5. Branch

## Branch란?

하나의 Repository 안에서 작업 영역을 분리하는 기능

```text
Repository
├── main
├── develop
└── feature/my-name
```

### 일반적인 작업 흐름

```bash
git switch develop
git pull origin develop
git switch -c feature/my-name
```

기능 개발 후

```bash
git add .
git commit -m "feat: my-name 기능 구현"
git push origin feature/my-name
```

그리고 GitHub에서

```text
feature/my-name
      ↓
Pull Request
      ↓
develop
```

로 진행한다

# 6. Merge와 Conflict

## 6-1. `git merge`

다른 Branch의 변경 내용을 현재 Branch에 병합한다

```bash
git switch develop
git merge feature/my-name
```

---

## 6-2. Conflict가 발생하면

Git이 자동으로 병합하지 못하면 conflict(충돌)가 발생하고

```text
develop|MERGING
```

처럼 표시된다

---

## 6-3. 해결 순서

### 1. 충돌 확인

```bash
git status
```

예시

```text
Unmerged paths:

  both modified: hello.txt
```

### 2. 충돌 파일 수정

파일에 다음과 같은 표시가 생긴다

```java
<<<<<<< HEAD
develop의 코드
=======
feature/my-name의 코드
>>>>>>> feature/my-name
```

의미

```text
<<<<<<< HEAD
→ 현재 Branch의 코드

=======
→ Merge 대상 Branch의 코드

>>>>>>> feature/my-name
→ Merge 대상 Branch 이름
```

원하는 최종 코드만 남기고 충돌 표시를 제거한다

### 3. 해결한 파일을 `add`

`git add`를 실행하여 충돌을 해결했다는 것을 Git에 알려준다

### 4. Merge 완료

`git commit`을 통해 병합을 완료한다

### 5. Push

```bash
git push origin develop
```

# 7. Commit 취소

## 7-1. `git revert`

기존 commit은 유지하면서 **그 commit의 변경 내용을 취소하는 새로운 commit**을 생성한다

예시

```text
A ── B ── C
         ↑
     파일 추가
```

```bash
git revert C
```

결과

```text
A ── B ── C ── D
              ↑
        C를 취소하는 commit
```

D는

```text
Revert "feat: 파일 추가"
```

와 같은 메시지를 가진다

# 8. Fork와 Clone

## 8-1. Fork

GitHub Repository 자체를 내 GitHub 계정으로 복사하는 기능

```text
원본 Repository
      ↓ Fork
내 GitHub Repository
```

주로 원본 Repository에 직접 push 권한이 없는 오픈소스 프로젝트에서 사용한다

---

## 8-2. Clone

Repository를 내 컴퓨터로 가져오는 작업

```text
GitHub Repository
      ↓ clone
내 컴퓨터
```

---

## Fork와 Clone 비교

| 개념     | 의미                           |
| ------ | ---------------------------- |
| Fork   | GitHub → GitHub              |
| Clone  | GitHub → 내 컴퓨터               |
| Branch | 하나의 Repository 내부에서 작업 영역 분리 |

---

## 8-3. Fork 작업 흐름

```text
원본 Repository
      │
      │ Fork
      ↓
내 Fork
      │
      │ git clone
      ↓
내 컴퓨터
      │
      │ Branch 생성
      ↓
개발
      │
      │ commit
      ↓
push
      │
      ↓
내 Fork
      │
      │ Pull Request
      ↓
원본 Repository
```
---
